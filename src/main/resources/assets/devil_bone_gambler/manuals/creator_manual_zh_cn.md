# 创建者手册

## 你是谁

- 存档第一次载入时, 第一位进入服务器的玩家被记录为创建者
- 创建者只记录一次, 之后不再改变, 也没有人能移除
- 创建者拥有管理员的全部能力, 并额外拥有名单管理权

## 只有你能做的事

- 在面板右上角的管理员窗口里增减管理员; 奖池配置与祭品价值配置你同样可以改

## 荷官的生成

- 只在世界时间走到日出或日落的整点时尝试, 每个整点最多生成一只荷官
- 候选玩家必须主手或副手持着赌徒的骰子, 不拿的不参与挑选
- 服务端打乱候选后依次尝试: 该玩家所在区块已有荷官就跳过, 找到能站的位置就在他附近生成
- 这条规则只写在这本手册里

## 手册的发放与收回

- 每次进入都按当前身份校准背包: 该有的补发, 不该有的收回
- 创建者手册与管理员手册不用刻意保管: 丢弃或掉到地上后, 片刻后会消失并补回一本

# 管理员手册

## 打开面板

- 按 Shift 加 D, 键位可以在控制界面改绑
- 或在游戏菜单的模组列表里选中本模组点配置按钮, 与按 Shift 加 D 完全等价
- 或执行 /devilbonegambler config, 短名 /dbgr config 等价
- 只有创建者与管理员能打开, 其他人按键没有反应

## 面板总览

- 顶部页签是奖池配置与祭品价值
- 上部编辑字段, 下部是表格: 表头冻结, 列宽固定, 过长内容裁切, 悬停可看全
- 滚动条可拖动, 状态行显示上一次操作的结果

## 奖池管理

- 面板右上角的 奖池 按钮打开奖池列表
- 一行一套奖池, 显示名称, 条目数与是否生效
- 选中一套后可以改名称与描述, 点 保存并启用 立即切换
- 新建会加一套只有一个空区域的奖池
- 删除要点两次, 确认按钮变红; 删除生效中的奖池会切到下一套, 删到一套不剩时自动建一套空白

## 奖池配置

- 表格列是区域, 条目名称, 权重, 颜色
- 新增区域会加一个区域, 区域编号对应骰子点数; 删除选中会连同该区域的条目一起删掉
- 新增条目在当前区域下加一行, 字段为区域编号, 条目名称, 权重, 颜色, 是否重大事件, 是否启用, 指令内容, 触发提示
- 条目名称就是一个字符串: 预设名称在生成配置时按当时的游戏语言写入, 之后不再随语言变化
- 权重越大越容易被抽到; 红色为正面, 黑色为负面
- 颜色, 重大事件与启用状态都是按钮, 点一下切换
- 指令内容可写多行, 每行一条原版指令, 开头的斜杠可以省略
- 支持占位符 ${player} 与 ${x} ${y} ${z}, 也支持 ${random:item} 这类随机令牌
- 指令校验不通过的条目不会被抽到, 状态行会说明原因
- 触发提示就是一个字符串, 只写奖品本身, 因为聊天框会显示 你获得了 s; 不要再写 你获得了 这类前缀, 也不会再出现翻译键或组件 JSON
- 触发提示留空时这条抽中后不显示提示

## 多选与删除

- 不按 Ctrl 点击为单选, 并清空之前的选择
- 按住 Ctrl 点击加入或移出选择, 最后点击的一行是主行
- 权重, 颜色, 重大事件, 启用, 指令内容与触发提示会写入全部选中条目
- 条目名称只写入主行
- 删除要点两次: 第一次只把文案换成确认, 在窗口内再点一次才真正删除; 超时或改动选择会恢复原状

## 祭品价值配置

- 表格列是名称与价值
- 祭品价值标签第一次点开这一页, 之后再点就在祭品价值, 物品价值与生物价值之间循环; 切换不会清空过滤框, 过滤框同时匹配名称与注册名
- 未登记的条目以弱化颜色显示, 悬停会说明原因
- 价值输入框在搜索框下方, 它下面的滑条与输入框显示同一个数: 滑条按整百大致拖动, 范围 0 到 100000, 输入框用于精确填写
- 填好的价值会写入全部选中条目

## 管理员名单

- 面板右上角的管理员按钮打开名单窗口, 其中列出创建者与全部管理员
- 只有创建者能增减管理员, 其他管理员只能查看
- 创建者不可被移除
- 输入玩家名字后点添加: 空输入, 重复的名字与创建者本人都被拒绝
- 名单改动对在线玩家立即生效, 离线玩家在下次进入时生效

## 荷官赌局的运维

- 一只荷官同一时间最多主持一场赌局, 招募一分钟
- 人数不足或发起者退出时赌局取消, 赌注与骰子全部退还
- 赌局进行中荷官被打死, 赌局中止并退还全部赌注与骰子, 玩家开着的荷官页面会自动关闭
- 荷官倒下会掉出背包里剩下的赌徒的骰子
- 招募开始几秒与开始前最后几秒有提示音, 便于判断节奏

## 提交与重载

- 提交把改动写盘; 修订号冲突时面板会载入最新配置, 再提交一次即可
- 保存失败时状态行给出原因
- 执行 /devilbonegambler reload(或 /dbgr reload)让服务端重新读取配置
- 这本手册跟随身份: 身份在就补发, 身份收回就一并收回; 丢弃后, 掉在地上的一本片刻后会消失并补回; 放进箱子等容器时, 关闭界面会回到背包

## 注意事项

- 除骰子点数那一行以外, 所有提示都进聊天框
- 指令按写下的内容原样执行, 改完先在单人存档里试一遍

## 模组指令占位符体系

占位符写在条目的指令里, 抽取时替换成真实内容. 触发提示只支持 ${player} 与 ${x} ${y} ${z}.

### 玩家与坐标

- ${player} 触发抽取的玩家名字
- ${x} ${y} ${z} 触发抽取的玩家坐标
- @(名字) 指定玩家的位置, 括号留空表示触发者
- #(名字) 或 #[名字] 指定玩家的祭坛位置; 佩戴祭坛时就是玩家脚下
- 位置占位符可以追加 [random=模式&范围], 范围上限 64: 模式 0 不扩散, 1 只沿 Z 轴, 2 在水平面, 3 在整个球体; 不写时按模式 0 与范围 6

### %(n,m) 随机整数

- 在 n 到 m 之间随机取一个整数, 闭区间, n 必须小于 m, 两端绝对值不超过 1000000
- 骰子抽取时, 目标值随点数升高, 溢出与幸运值继续抬升; 红点偏大, 黑点偏小
- /dbgr run 试跑没有抽取上下文, 在区间内均匀抽取
- 例: give ${player} minecraft:bread %(4,16)

### --R(n) 重复执行

- 只能写在指令行末, 行末空白不计; n 是 1 到 10 的整数
- 这一行会执行 n 次, 每次的其他占位符都重新展开, 因此随机整数与样本空间可以每次不同
- 有非法 n 或占位符不在行末的条目不会通过校验
- 例: give ${player} minecraft:bread 1 --R(5)

### 随机令牌

- ${random:item} 随机物品, ${random:effect} 随机效果, ${random:entity} 随机实体, ${random:enchantment} 随机附魔, ${random:potion} 随机药水
- 池子在世界加载时按当前安装内容重建, 写到配置目录的 random_pools.json

### 样本空间

- ^(类型) 或 ^(类型)[命名空间], 模组在这个类型的样本空间里挑一个 ID 替换掉它
- 类型由模组在每次世界加载后从当前游戏内容自动识别, 结果写到 sample_spaces.json, 换游戏版本或装新模组后只更新这个文件
- 省略方括号时不限命名空间, 写了方括号就只在该命名空间里挑
- 红点只在正面样本里挑, 黑点只在负面样本里挑, 该类型没有对应样本时回退到全部样本
- 点数与溢出越高, 越偏向样本空间里稀有的那部分; 幸运值越高也越偏向稀有与正面样本
- 通用类型: ITEM 物品, BLOCK 可取得物品的方块, ENTITY 实体类型, MOB 可生成的生物, EFFECT 状态效果, ENCHANTMENT 附魔, POTION 药水, SOUND 音效, PARTICLE 粒子, PAINTING 画, ATTRIBUTE 属性, FLUID 流体, BIOME 生物群系, STRUCTURE 结构, DAMAGE_TYPE 伤害类型
- 细分类型: BUFF 正面效果, DEBUFF 负面效果, NEUBUFF 中立效果, BUFF_ENCHANTMENT 正面附魔, CURSE 诅咒附魔, ENCHANTED_BOOK 直接给出一本带附魔的附魔书
- 一个指令行里可以写多个占位符, 每个各自独立抽一次
- 占位符只抽注册 ID, 不会在世界里生成实体或方块实例; 附魔书是唯一例外
- 抽中后, 样本名称会追加在触发提示后面, 用空格分隔; 没用占位符的条目不受影响

### 校验与试跑

- 未知类型, 命名空间过滤后为空, 空区间与超界都会让条目校验失败
- 校验时把占位符替换成代表样本再交给原版解析器
- 可以直接在聊天框试: /dbgr run <带占位符的指令>, 只有创建者与管理员能用
- 占位符里的 ID 只是在指令里替换成文本, 指令本身仍按原版语法执行, 改完先在单人存档里试一遍
